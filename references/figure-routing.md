# 图形路由与证据链

## 先确定“图要回答什么”

| 评委问题 | 首选图形 | 应呈现的证据 |
|---|---|---|
| 你们如何把题目变成模型？ | 模型总框架图 | 输入、假设、变量、子模型、约束、输出 |
| 算法如何运行？ | 流程图或泳道图 | 初始化、迭代、判断、更新、停止条件 |
| 模型机制是否合理？ | 原理/几何/状态转移示意图 | 关键量之间的方向和约束关系 |
| 拟合或预测效果怎样？ | 真实值-预测值图 + 残差图 | 误差分布、偏差、异常点、指标 |
| 方案是否更优？ | 排序点图、带误差的对比图、Pareto 图 | 基线、候选方案、改进幅度、约束满足 |
| 结果是否稳健？ | 敏感性曲线、龙卷风图、热力图 | 参数扰动范围、响应方向、稳定区间 |
| 空间或路径方案是什么？ | 地图/网络/轨迹/覆盖图 | 位置、方向、容量或时间编码 |
| 分类或聚类是否可信？ | 混淆矩阵、降维散点、轮廓系数图 | 类间分离、错误类型、样本数量 |

## CUMCM 推荐最小图组

不要机械追求数量。常见完整证据链是：

1. 一张题意到模型的总框架图。
2. 每个真正复杂的求解器一张算法流程图；简单闭式计算不单独画。
3. 每问一到两张核心结果图。
4. 全文至少一张误差、敏感性或稳健性图。
5. 若有优化，再增加基线对比或 Pareto/约束满足图。

## 模型框架图

建议从左到右或从上到下形成唯一主线：

题目数据 → 清洗/特征 → 假设与变量 → 子模型 → 求解器 → 验证 → 结论

- 同层节点语法一致，使用“动词 + 对象”或“名词短语”，不要混用整段句子。
- 数据、模型、算法、结果用颜色或分区区分，但不超过三类主色。
- 跨层反馈边使用虚线并写明反馈含义。
- 多问之间共享的模块只画一次，通过编号或端口连接。

## 算法流程图

- 起止：圆角/椭圆。
- 操作：矩形。
- 判断：菱形或显著不同的判断节点；边上明确“是/否”。
- 输入输出：平行四边形或带标签的数据节点。
- 迭代必须能沿箭头回到更新或判断节点；停止条件必须可见。
- 复杂算法优先按“初始化 → 评价 → 更新 → 约束处理 → 收敛判断 → 输出”组织。

## 结果图

- 预测问题：真实值与预测值共轴，另设残差或相对误差面板。
- 优化问题：展示基线、最优方案、关键约束和稳定性，不只给最优数值。
- 评价问题：优先点图/条形图配置信区间，权重与得分分开表达。
- 时序问题：标出训练/验证边界、关键事件和预测区间。
- 空间问题：保持坐标比例，给比例尺/单位，避免用颜色同时编码两个变量。

## 图题和正文回扣

图题写结论，不写“某某结果图”。例如：

- 好：参数在 0.8–1.2 倍扰动下，最优方案排序保持稳定
- 弱：敏感性分析结果图

正文至少回答：看到了什么、为什么支持模型、是否存在例外或限制。
