# 论文图版式与标注模式（通用经验）

这份参考用于地图、网络、算法流程、模型框架、结果空间和多目标优化图。它记录的是可迁移的设计决策，不绑定某一道题或某组数据。

## 1. 先写“看完图要记住什么”

在代码或 Visio 文件开始处记录一句核心结论，并只保留能支撑这句话的视觉元素。若一张图同时承担“输入—算法—结果”三个结论，应拆图或做带编号的两级图，而不是继续缩小字体。

建议阅读顺序：

1. 主对象（节点、路径、点云或流程阶段）；
2. 主关系（箭头、支配、分区、比较或误差）；
3. 少量直接标签；
4. 图外短注和论文正文解释。

## 2. 分层绘制顺序

结果图和网络图通常按以下层级绘制：

1. 画布、网格和辅助边；
2. 主路径、主系列或参考线；
3. 次路径、次系列和不确定性；
4. 节点/标记边框；
5. 节点文字、数据标签和短注。

同一对象不要在多个层级重复绘制。尤其不要先画节点再把连接线覆盖到节点内部，除非这种穿越本身具有明确语义。

## 3. 节点与连接线

- 节点填充默认为透明，避免白色圆圈意外遮住路径或造成“底色块”。
- 节点需要遮挡连接线时，必须把遮挡作为有意编码，并在图形契约中说明；否则使用透明填充、连接线端点收缩或边界裁剪。
- 先用一个普通节点校准圆圈大小、边框宽度和字母字号，再统一到全部节点。重点节点可以使用颜色或标记强调，但不要仅靠放大到遮挡线路。
- 箭头端点应停在节点边界，使用 `shrinkA/shrinkB`、端点几何或裁剪实现；不要依赖“画完节点后恰好盖住”。

## 4. 共享边与重叠系列

两条路径共享一条边时，先选择一种表达策略：

- **单层策略（默认）**：共享边只画一次，使用语义明确的颜色/线型；其余路径只画独有边。适合论文原理图和小型网络。
- **并行策略**：两条边使用小幅对称偏移或弧线，适合必须同时追踪两条路径的场景。
- **分段策略**：共享段用连续线，独有段保留各自线型，并在图例或正文中说明。

禁止把橙色虚线直接叠在蓝色实线上而不处理底层线，因为虚线间隙会露出蓝色，读者会误判为第三种路径。若采用单层策略，节点附近也要检查是否有旧图层残留。

## 5. 标签和说明

- 首选普通文字 + 手动偏移；标签避开节点、箭头尖端、虚线交点和坐标刻度。
- 默认不使用 `bbox`、圆角色块或不透明背景。文字与线条冲突时先调整位置、缩短文本或换线型；最后才考虑白色描边/光晕，且保持填充透明。
- 坐标区内只保留变量名、短标签和必要数值。把“因此……”“算法首先……”等论文句子放到图外或正文。
- 标签颜色应与对应系列一致或使用统一深灰；不要让标签颜色和数据系列含义冲突。
- 图外标题、结论句和底部注释各自占据独立留白区，不能贴在同一行或被 `tight` 裁切。

## 6. 复杂模型的两级图与投影

- 主图展示整体关系，小图展示一个关键局部；小图必须有编号、指向或一致的颜色映射。
- 三维模型可以用二维投影解释索引、分区或邻域查询，但标题/注释必须写明投影轴，正文说明实际计算仍在原始维度进行。
- 3D 图只放点、轴、短标签和必要结论；不要把算法段落放进坐标主体。若视角导致标签拥挤，换视角、拆图或改用二维示意。

## 7. 版面与导出

- 在正式论文插入宽度下检查，而不是只看屏幕上的原始画布。
- `bbox_inches="tight"` 可能裁掉留白并降低像素宽度；遇到门槛失败时先提高 DPI，保持物理插入尺寸，再重新检查标题和注释是否被裁切。
- 论文图通常使用白底、少色、高对比。主色、强调色和中性灰在全文保持一致；用线型/标记补充颜色编码。
- 生成 PNG 后重新打开并运行 `validate_png.py`，再人工检查：文字、边界、透明填充、共享边、灰度可辨识度和最终缩放效果。

## 8. 失败模式速查

| 现象 | 常见原因 | 修正方向 |
| --- | --- | --- |
| 虚线间露出另一种颜色 | 共享边重复叠画 | 单层或并行策略，明确共享段 |
| 标签有白块、压住线 | 不透明 `bbox` | 手动偏移，必要时仅白色描边 |
| 节点像贴纸一样盖住线路 | 默认白色填充 | 改透明填充，或让连接线停在边界 |
| 图放进论文后字太小 | 画布没有按插入宽度设计 | 拆图、减少文字、提高 DPI 保持物理尺寸 |
| 3D 图信息太多 | 把解释段落塞进坐标区 | 坐标外短结论，或改为二维投影/两级图 |
| 重点系列不突出 | 颜色、线型、层级不一致 | 统一语义编码，主系列最后绘制并直接标注 |
